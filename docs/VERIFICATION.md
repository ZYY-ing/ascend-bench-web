# 独立 Runner 测试逻辑验收（2026-11-07—08）

本次针对 `ascend-bench-web` 独立工具包，参考中心版已经排查过的问题修正测试内部实现。保留自行准备 Docker 容器、执行 `setup.sh`、建立 SSH 隧道、使用 token 登录的部署方式；没有引入中心服务或管理员核验步骤。`setup.sh` 与修改前工具包逐字节相同。

结论：下表中的小批量精度、性能、故障处理和原规模数据集生成均完成验证。**原始全量精度、450 并发、600 秒持续压测没有执行，不能据此宣称全部原规模用例通过。** 本次是功能验收，不是工具与纯 CLI 的性能开销对照实验。

## 环境和验证方法

- 服务 A 为已有健康的 MiniMax 服务，上下文上限 133000 tokens；客户端 B 与 A 同网段，跨机直连。
- 在 B 创建三个独立测试容器：R1 执行模型测试，R2 并行生成数据，R3 验证原安装流程和最终工具包。R1/R2 各限 4 核、12 GiB，R3 限 2 核、8 GiB；均非特权、没有 NPU 设备挂载。
- 测试前确认 A 的健康接口正常、等待/运行请求为零、请求计数短时稳定且未发现外部 AISBench 测试进程。后续使用低并发，不启动、停止、重启或清缓存于 A 的服务；故障模拟仅使用自建回环服务。
- 实机按网页使用的 HTTP 接口执行登录、连接服务、生成数据、提交任务、轮询、查看结果与下载；前端表单转换另用 JavaScript 回归验证。**没有声称逐个按钮做了浏览器鼠标端到端测试，也没有测量 SSH 隧道或浏览器渲染延迟。**
- 随包固定 AISBench 3.1.0；与旧包对比，1616 个 benchmark Python 源文件保持一致。兼容适配、参数生成和日志收集在 Runner 层；不修改原生稳态识别算法、评分器和指标公式。
- 每个任务保留配置、命令、原生输出及结果文件作为私有证据；公开文档只用 A/B、R1/R2/R3，不发布地址、登录信息、真实容器名或题目内容。

## 修复内容及原生映射

| 网页功能 | 最终行为 |
| --- | --- |
| 精度/性能模式 | `all` / `perf`；保留 `perf + reuse` 的原生行为，额外参数不能覆盖 mode |
| 并发 | `models[0].batch_size`；不生成版本不支持的 `--batch-size` |
| 接口与流式 | Chat/Completions 对应不同原生 API 类；`stream` 直接传入 |
| 模型顶层参数 | 例如 `request_rate`、`retry` 写到模型配置；retry 不加一、不转换含义 |
| 生成参数 | `top_p`、`top_k`、惩罚、`skip_special_tokens` 等进入 `generation_kwargs`；其他字段可用 `generation_kwargs.字段=JSON值` |
| CLI 参数 | 例如 `debug=false,max_num_workers=2` 控制命令行；与模型/生成参数分别处理 |
| 超时 | 默认原生不限时，自定义时传原值；不添加整个任务的两小时上限；异常断连进入原生重试 |
| 预热 | 重放数据集前 N 条；数量 0–样本数；默认最大输出跟随正式输出，独立输出上限由适配层实现，不冒充原生命令行开关 |
| 稳态 | 选择原生 `StablePerfMetricCalculator`；无法形成窗口时保留原生报错 |
| pressure | 原生 `--pressure --pressure-time 秒数`；与稳态选择独立，正式请求量可超过数据集条目数 |
| 数据生成 | 独立进程、异步进度；缓存校验参数及 tokenizer 指纹，同目录写入互锁；只读 tokenizer 不互锁 |
| 日志 | 原生 debug/非 debug 日志合流；状态轮询只读尾部，显式导出才读取完整日志，服务端分块发送 |
| 任务结果 | 保留原生退出结果及表格；缺评分、失败请求、长度差异显式提示，不伪造分数、不改写原始统计 |
| 空闲恢复 | 任务进程及活跃子进程退出后恢复空闲，僵尸进程不再永久占用 Runner |

独立 Runner 仅管理自身活动和共享缓存写入，没有中心版跨 Runner 的全局服务互锁。不同 Runner 对同一服务发压测前，仍需由使用者协调。

## 故障模拟

P20/P21 各 16 条、并发 4，只向独立回环故障服务发送，不破坏真实 vLLM。每项人为让 2 个输入持续失败，14 个成功。

- P20：请求超时 1 秒；P21：保持原生不限时，服务主动中断连接。
- `retry=2` 原值传入，本次原生实现对每个失败输入实际尝试 2 次；其余输入各 1 次。不存在网页偷偷加一。
- 两项均正确记录 2 条失败、显示提示、日志可查，结束后自动空闲；故障服务随私有测试环境退出。
- 此 AISBench 版本在这类部分失败任务中仍返回退出码 0，因此网页保留“完成”并明确显示失败计数；不能把“完成”理解为全部请求成功。

## 日志、安装与本地回归

- 最终安装包真实 HTTP 下载验证：540034 字节日志首尾及 SHA256 一致；轮询仅保留 200000 字符尾部，导出完整文件。原生指标内容不拆表、不重算；纯文本表格在比例字体或强制折行的编辑器中仍可能错位。

## 尚未验证及使用约束

没有运行原始全量精度和超长实际输出、原始高并发/600 秒组合；没有证明任意模型的思考参数语义、任意服务容量、所有接口实现或跨网性能；没有把静态配置通过冒充模型实测。稳态找不到窗口、服务拒绝超上下文请求或不支持字段时，遵循原生报错。

测试完成后仅归档并清理本次三个私有容器和各自临时目录，保留其他人的容器、任务结果、共享缓存及模型服务。后续独立部署从当前 main 的包获取修复，旧 Release 和 CDN 缓存不会自动更新。
